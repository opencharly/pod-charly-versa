# AGENTS.md — pod-charly-versa

Standalone candy repo for the `charly-versa` candy — a metadata concept candy
owning the `skill:` entities for the versa family whose names have no namesake
candy. The entire candy lives in `charly.yml` at the repo root: the
`charly-versa:` entity plus seven `skill:` entities. There is no source tree and
no install content — the entities are the product.

Canonical files:

- `charly.yml` — the `charly-versa` candy entity plus the seven `skill:` entities
  (`airflow-layer`, `debug-tools-layer`, `maputnik-layer`, `marimo-layer`,
  `marimo-mcp`, `osm-tools-layer`, `sway-browser-ecovoyage`).
- `.github/workflows/tag-on-merge.yml` — CalVer tag + `CHANGELOG/` on merge.
- `CHANGELOG/` — per-CalVer history.
- `README.md` — user overview only; never agent guidance.

## Load these skills first (R0)

- `/charly-internals:skills` — the owning procedure: when and how to update a
  `skill:` entity and regenerate the marketplace corpus. Load before editing any
  entity here.
- `/charly-internals:marketplace` — how the corpus is generated and consumed.
- `/charly-internals:git-workflow` — before any git/PR action.

The skills projected from this repo are `/charly-versa:airflow-layer`,
`/charly-versa:debug-tools-layer`, `/charly-versa:maputnik-layer`,
`/charly-versa:marimo-layer`, `/charly-versa:marimo-mcp`,
`/charly-versa:osm-tools-layer`, and `/charly-versa:sway-browser-ecovoyage`; each
is the owning procedure for the versa component it documents.

## Build / validate / test

- `charly box validate` at the repo root — the structural check: the manifest
  must parse and validate at the installed charly.
- The merge gate is the **org-wide** `charly/pr-validator` (required check
  `validate / validate`, defined in `opencharly/.github`); this repo has **no**
  per-repo candy gate. Its only workflow file is
  `.github/workflows/tag-on-merge.yml`.
- The `skill:` entities are projected into the marketplace corpus; the
  marketplace repo's own drift gate and the docs build validate the projection.

## Modify this repo

- Edit a `skill:` entity in `charly.yml` — the entity is the source; the
  projected `versa/skills/*/SKILL.md` carries a DO-NOT-EDIT banner and is
  regenerated by `charly marketplace generate`.
- A dangling `/charly-<plugin>:<skill>` cross-reference in a skill body breaks
  the docs build; sweep every reference when a skill is renamed or deleted.
- Keep the concept candy's plan the validate-satisfying no-op it is; there is
  nothing to install.

## Landing

- PR-only. Every change lands through a pull request; the org-required
  `charly/pr-validator` validates the diff and body and arms native auto-merge
  on PASS. Direct pushes to `main` are blocked.
- History lives in `CHANGELOG/` (written by `tag-on-merge` at merge time); the
  PR body IS the changelog.
- The authoritative rulebook is the umbrella `AGENTS.md` in
  `opencharly/opencharly` and `charly/AGENTS.md` in the charly repo. Do not
  restate its rules here.
